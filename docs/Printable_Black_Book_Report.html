ABSTRACT

Collegiate campuses span extensive physical facilities where thousands of students, faculty, and administrative staff move across classrooms, multi-floor libraries, laboratories, sports pavilions, and dining facilities daily. Due to this high transit density, personal assetsâ€”such as scientific calculators, laptops, university identity cards, room keys, and backpacksâ€”are frequently misplaced.

Conventional lost-and-found practices rely on manual security gate registers, paper corkboard flyers, or informal WhatsApp group chats. These approaches are unorganized, unsearchable, lack visual documentation, and present high vulnerability to fraudulent claims.

CampusTrack is an automated, web-based Lost and Found ecosystem engineered to solve these challenges. Employing a modern three-tier decoupled architectureâ€”comprising React 19, Tailwind CSS, Node.js Express 5, and an embedded SQLite database managed through Prisma ORMâ€”the application introduces an Anti-Fraud Security Challenge Protocol. CHAPTER 1: INTRODUCTION

1.1 Background & Motivation

In modern higher education institutions, sprawling physical facilities host thousands of daily interactions among students, research scholars, teaching faculty, and administrative staff. As individuals transition between instructional lecture halls, departmental computer centers, multi-story libraries, and food courts, personal possessions are regularly left behind. Misplacing items such as graphing calculators before examinations or smart identity cards necessary for campus turnstile access causes serious logistical and academic disruption.

Historically, universities have handled misplaced property through decentralized channels: physical paper registers at security gates, flyers taped to bulletin boards, or unofficial student WhatsApp batches. These methods lack search indexing, photographic records, ownership proof, and institutional accountability.

1.2 Scope of the Project

CampusTrack provides a centralized university portal that digitizes the entire recovery lifecycle:

  • Categorized application logging for both lost items and found articles.
  • Server-side multipart image processing linking photographs directly to database records.
  • Challenge-response anti-fraud ownership verification questions.
  • Administrative security portal enabling moderation and audit tracking across campus.

CHAPTER 2: PROBLEM DEFINITION

2.1 Core Problem Statement

The absence of an automated, centralized digital tracking system in collegiate institutions results in permanent property loss, wasted student hours, vulnerability to fraudulent claims, and heavy administrative overhead on security staff.

2.2 Key Operational Bottlenecks

  • Information Fragmentation: Notices are scattered across separate physical buildings and unofficial social media channels with zero cross-campus coordination.
  • False Claims & Scams: In public chat groups, opportunistic individuals falsely claim items because finders lack verification protocols.
  • Absence of Photographic Evidence: Physical notebooks cannot capture visual condition, brand stickers, or subtle identifying marks.
  • Privacy Vulnerabilities: Students frequently post their private mobile numbers on public corkboards, leading to unsolicited calls.

CHAPTER 3: OBJECTIVES

The principal engineering objectives of CampusTrack are:

  1. Centralized Discovery: Build a unified web application serving all departments, hostels, and campus administrative centers.
  2. Integrated Image Storage: Implement a robust media upload subsystem using Multer to archive photos of lost and found items on disk.
  3. Anti-Fraud Verification: Implement an ownership verification mechanism requiring claimants to provide specific hidden details or answer challenge questions.
  4. Student Privacy Protection: Provide in-app claim notifications so students do not need to publish phone numbers publicly.
  5. Administrative Governance: Provide campus security personnel with a real-time console to track statistics, monitor disputes, and delete spam.
  6. Zero-Setup Portability: Use Prisma ORM and SQLite so the entire application and database can run on any laptop or cloud container with zero configuration.

CHAPTER 4: REQUIREMENT SPECIFICATION

4.1 Functional Requirements

  • Authentication: Secure registration/login with university email, student ID, and Bcrypt password hashing.
  • Reporting: Dual forms for lost and found items with title, category, campus location coordinates, date, and photo.
  • Search & Filter: Live instant search across keywords, building locations, categories, and item status.
  • Claims Workflow: Claim submission with verification answers and proof photos; poster review with Approve/Reject actions.
  • Security Panel: Administrative metrics, user directory, and moderation controls.

CHAPTER 6: PROPOSED SYSTEM

6.1 System Overview & Benefits

CampusTrack establishes a clear, accountable lifecycle for misplaced belongings. When a student finds an item, they log its campus coordinates, attach a photo, and set an Ownership Verification Question (e.g., "What color is the keychain charm?"). Claimants must answer this question and can upload proof (e.g., purchase invoice, student ID) to claim the item. The item poster reviews the claim and approves it, automatically marking the case as RESOLVED.

  • Fraud Mitigation: Prevents opportunists from taking belongings they did not lose.
  • Photo Preservation: Actual images stored locally on disk and served statically.
  • Privacy Shield: Contact information is only shared after verification approval.

CHAPTER 7: SYSTEM ANALYSIS & DESIGN

7.1 Three-Tier Architecture

The platform follows a decoupled three-tier architectural model:

  • Presentation Tier: React 19 UI with Tailwind CSS providing high accessibility across devices.
  • Application Tier: Node.js Express server handling business logic, Multer file streaming, and JWT tokens.
  • Data Tier: Prisma ORM managing SQLite database relations (dev.db) and static image assets (/uploads).

CHAPTER 12: CONCLUSION

CampusTrack successfully demonstrates how modern web engineering can solve a persistent real-world collegiate challenge. By uniting React 19, Express.js, and SQLite with Prisma ORM, the project establishes a centralized platform that eliminates information fragmentation, prevents false claims via verification questions, archives photo evidence, and provides campus authorities with full oversight.
